## 确定性对照证明什么

`wait-work-loader.spec.ts` 经真实 Loader/Include/YAML 启动真实普通 loop。模型和外部读取使用可控模拟：两组均完成同一文本准备与读取任务，启用组在单工具返回前完成准备，下一主请求消费候选材料与实际工具输出；默认组不新增辅助调用。最终输出一致。

此对照证明调度重叠、消息配对、结果传递及持久化链路，不证明真实模型一定给出有用提案，也不证明真实 token、费用或延迟下降。测试使用事件顺序断言，不以墙钟加速比作为通过条件。

## 尚未证明的能力

- 未进行真实 provider 的质量、费用和端到端收益评测。
- 不覆盖 exclusive 工具、prepare/权限等待、finalize 等全部等待区间。
- 非合作 provider 无法强杀；其槽位保持占用至退出，主 loop 不等待它。
- 辅助事件为实时统计，迟到 usage 不补写，未知值为 null；不是完整计费账本或跨进程恢复。
- 滚动补位和 parallel/exclusive 混合序列另经独立模拟探针验证，尚无新增的观察者专项真实-runtime 混合序列回归。

结论：达到默认关闭的实验功能提交标准，不构成生产成熟度或普适加速承诺。
